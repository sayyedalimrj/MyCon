# MyCON Scientific Validation Protocol v1 — preregistered 2026-11-12

## 1. Objective, reference and non-equivalence

Reference: Duran, A., Waibel, C., Bickel, B., Armeni, I. and Schlueter, A. (2027 journal issue, DOI 10.1016/j.autcon.2026.107294), *Automated facade solar retrofits using feed-forward 3D reconstruction and generative image editing*; accompanying implementation: https://github.com/ycdrn/image2bipv. Reference uses DUSt3R/VGGT, GeoCalib for gravity, facade masking / orthorectification, VLM-based metric size, diffusion editing and solar-potential estimates. Its stated aspect-ratio errors (9%/15% on two datasets) and floor count error (~0.5) are **not** estimates of construction physical-progress accuracy. They cannot be pasted into a MyCON benchmark table as a like-for-like comparison. If an aspect-ratio task is later added, measure both pipelines on a common annotated facade set and report different image coverage conditions.

MyCON's test target is actual reconstruction quality and **metric** BIM alignment; confidence-qualified element status; physical progress and schedule claims. Baselines must run on the same capture budgets, GT frame, hardware class, and dataset split. Compare COLMAP classical SfM/MVS, existing MyCON stages, and optional DUSt3R, VGGT, 3DGS/CAMS-GS only when their executable versions, checkpoints, licenses and output artefacts are available. Any unavailable baseline is `not_executed`.

## 2. Independent Ground Truth acquisition (before model evaluation)

1. Register a site/building/capture-session inventory and chain-of-custody. Record device, focal length and calibration, capture timestamp, date, weather/illumination, camera positions, occlusion, camera motion, construction stage, source immutable SHA256 and privacy permissions.
2. For each site, acquire independently surveyed control points: >=4 well-distributed non-coplanar 3D targets where feasible, measured in metres using total station / terrestrial LiDAR, with instrument accuracy, control network, coordinate reference frame, and uncertainty report. Never generate ground truth from MyCON predicted geometry.
3. Independently survey as-built facade/building surfaces (registered laser scan or calibrated survey) at the *same construction date*. Exclude moving people, scaffolding and temporarily occluded/non-target surfaces via documented shared masks. Freeze sample/resampling density and evaluation tau before seeing test results.
4. Establish approved IFC element inventory from signed design/as-built change register. Inspect `GlobalId` uniqueness, IFC entity class and design-to-as-built validity, with change orders, element boundaries, tolerances and discipline. Do not use the same IFC file as both prediction and independent GT uncritically.
5. For physical progress, two blinded quantity surveyors independently label each `global_id` as built/partial/not_built, completion fraction by accepted quantity (not image visibility), activity mapping and measurement date. Resolve disputes by third-party adjudication; log disagreement (Cohen kappa/ICC where appropriate), exclusions, weight basis (BOQ/cost or quantity) and approval signatures.
6. For elements outside camera FOV, mark photographic evidence **unknown**, but retain independently determined construction state in GT. `not_evidenced` is never a negative. Freeze all annotation sheets and hashes before tests, store outside the code repository, release only appropriately anonymized subsets.

## 3. Frozen train/validation/test partition and leakage audit

Split by **whole site** as the outermost independent unit; no building, capture-session, source SHA256 or near-duplicate imagery crosses partitions. Suggested target split by sites 60/20/20 where feasible (report actual counts, no artificial equality); small site cohorts should use leave-one-site-out cross-validation with strictly nested tuning. Train on train, tune hyperparameters/thresholds and select checkpoints on validation, evaluate final held-out test exactly once; repeated probes constitute leakage. Keep sequential visits from the same building in the same partition. Use perceptual near-duplicate audit offline, plus this harness's exact-byte/source-id checks. Persist manifest, deterministic split seed, hash and reviewer sign-off. Test dates and construction epochs remain specified to avoid confusing design change with temporal variation.

For generalizability stratify site types, construction stages, geometry complexity, indoor/outdoor, camera baseline, lighting, occlusion, and BIM completeness; stratify within the site-level grouping constraint, not by reusing images. If few test sites, avoid overconfident CIs.

## 4. Predefined metrics and statistical analysis

- **Reconstruction**: symmetric Euclidean Chamfer L1 in metres and squared Chamfer L2 in m²; precision/recall/F-score at tau = 0.05 m as default and sensitivity thresholds 0.01/0.02/0.10 m. Use uniform surface sampling/registered coordinate frame; record n sampled vs total and point-cloud density. Report failure of model output separately from metric score.
- **BIM registration**: absolute target registration error (TRE) on independent surveyed correspondences: mean, RMSE, 95th percentile metres; metric scale ratio of predicted vs GT anchor-pair distance, drift %; matched IFC GlobalId inventory precision/recall and class accuracy. If BIM as-built truth exists, evaluate aligned point clouds separately (not just in-sample ICP fitness). Report quality-gate and unregistered cases.
- **Progress**: 3-class selective precision/recall/F1 with fixed known-label denominator; unknown/abstention rate separately across all GT elements. Fractional weighted MAE only for numeric independent GT vs method physical_progress_estimate pairs; report n and weight coverage. Report overall physical-progress feasible bound under unknown elements, never call it an estimated point value. Brier score and 10-bin ECE apply only to predicted correctness confidence, on classified elements. Plot coverage vs risk and reliability only after real evidence exists; confidence is not the same thing as observability.
- **Efficiency**: same input image count/resolution and common hardware, record wall time, GPU peak allocated memory/VRAM, peak RSS, wall-time measurement tool, hardware, CUDA/driver and model/checkpoint SHA. Missing runs and failures report explicit counts rather than being dropped silently. Per-task failure denominators are attempted runs; also disclose missing/not_executed runs.
- **Uncertainty**: 2,000 seeded nonparametric **site/building-cluster bootstrap** draws for descriptive 95% percentile intervals; no point bootstrap mistaken for sample independence. At least 2 independent buildings for an interval; collect more for publication. Compute paired method delta only on intersecting sample IDs and matched GT, with paired cluster CIs. Predefine primary metric and multiplicity correction for formal hypothesis testing if many ablations are evaluated. No superior claim from a CI alone, no invented p-values.

## 5. Ablation preregistration

See `repository/configs/research_validation/ablation_plan.json` for full vs no-depth-prior, no-CAMS-GS, no-metric-anchor, no-ICP, no-multiview-fusion, no-observability-gate, no-calibration. Owner A/B produce variants in their OWN files and publish outputs to separate paths. Owner C consumes frozen outputs using method names in a common manifest; never changes pipeline source or re-trains unless agreed with lead. Fix seeds [11,23,42,67,101], metrics, capture splits and hardware class. Each ablation must report any missing output, error mode, time and memory, and GT qualification. In particular, disabling observability gates is a diagnostic-only unsafe variant and must not feed real schedule decisions.

## 6. Failure taxonomy and research paper ready tables

Failure codes: missing capture; bad/unreadable PLY; coordinate frame mismatch; insufficient anchors; invalid IFC IDs; unsupported geometry density; wrong element identity; camera occlusion; withheld validation; missing ground truth; missing model output; timeout/OOM; indeterminate evidence/abstention; registration quality gate fail; incorrect scale; privacy exclusion. Report examples by site and construction stage, stratified false positives/negatives and reviewer notes. Include *non-commensurate comparison* disclaimer when citing published results from different datasets.

Preplanned thesis tables: (T1) capture/site/GT sample distribution and exclusion counts; (T2) reconstruction/registration: mean and 95% cluster CI, thresholds and runtimes; (T3) precision/recall/F1 unknown rate and percentage MAE with denominators; (T4) paired baseline deltas across common sites; (T5) 5-seed ablation matrix and effect sizes; (T6) failure modes and cost tradeoffs. Figures: geometry metric/CI, calibration reliability diagram, risk vs coverage, failure frequency and paired deltas. `thesis_table.md` plus `comparison.csv` are generated from actual scored data, not manually filled numbers.

## 7. Mandatory reproducibility checklist

- Manifest SHA256, raw capture SHA256, every GT and prediction file SHA256, method Git commit, checkpoint SHA256; verified reviewer IDs and measurement dates.
- Python, SciPy, CUDA/torch/Open3D/IfcOpenShell, COLMAP and OS/driver versions and deterministic seeds; actual VRAM, CPU/RAM, GPU, runtime/cost, exact train/eval flags.
- Full collection and exclusion counts by site, building, session, date and label. Normalized [0,1] confidence/physical fraction and explicit metres in geometry. Never mix percent 0–100 with fraction 0–1.
- Locked thresholds, annotation disagreement, accepted quality gates, failure logs and per-sample outputs retained under unique `bench-` run IDs.
- No source delete or `--force`, no colliding A/B run directories, no PR merged by Owner C.

**Evidence status on protocol publication:** tooling unit-tested on synthetic fixtures; no verified held-out MyCON ground truth or corresponding baseline results evaluated. All real thesis metrics are `not_executed` pending verified inputs.
